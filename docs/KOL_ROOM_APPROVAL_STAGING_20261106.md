## Область работ
Отдельная функциональность **045 Room Lifecycle**, не входящая в уже проверенные 44 SQL-миграции. Изолированная база `kol-isolated-44` восстановлена из реального облачного бэкапа; основная Supabase **не изменялась**. PR #156 остаётся Draft.

## Что реализовано
- SQL: `supabase/schema/045_admin_room_lifecycle_DRAFT_NOT_APPLIED.sql` — узкое аудируемое RPC `admin_room_lifecycle_atomic`.
- Проверка SQL: `supabase/schema/045_admin_room_lifecycle_VERIFY.sql`.
- Server action: `src/app/actions/admin/adminRoomLifecycle.ts`, использует `requireSuperAdmin`, проверяет идентификаторы, действие, длину причины и request ID.
- Админка: `/admin/catalog/rooms`, ссылка из раздела управления жильём. Каждое решение относится только к одному номеру, требует причины и имеет ID идемпотентности.
- Статусы: `under_review -> approved` или `under_review -> rejected`; затем `approved -> active`; `active -> approved` для снятия с публикации.
- **Одобрение не означает автоматически публикацию.** При нулевой или некорректной цене, неверной вместимости и неактивном партнёре действие не проводится. Демо-номер отклоняется.
- `super_admin` получает только право SELECT для модерации номеров. Прямые INSERT/UPDATE/DELETE для anon/authenticated закрыты. Мутации только через RPC с записью в `audit_logs`; запросы повторно используются только с идентичными параметрами.
