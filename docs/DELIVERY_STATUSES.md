# KÖL — Delivery Statuses

Документ фиксирует статусы доставки и курьерского контура платформы KÖL. На этом этапе это только спецификация: backend, Supabase, Telegram, n8n, платежи и alcohol delivery не подключаются. `ALCOHOL_MODULE_ENABLED=false` по умолчанию.

## 1. Order preparation statuses

Эти статусы описывают готовность заказа у партнёра до и во время передачи в доставку.

| Status | Назначение | Кто меняет | Что видит клиент |
| --- | --- | --- | --- |
| `new` | Заказ создан и ожидает реакции партнёра. | Система после checkout demo | Заказ создан. |
| `partner_accepted` | Партнёр принял заказ в работу. | Партнёр | Партнёр подтвердил заказ. |
| `partner_rejected` | Партнёр отклонил заказ. | Партнёр / админ | Заказ отклонён, нужна причина. |
| `preparing` | Партнёр готовит еду или собирает товары. | Партнёр | Заказ готовится. |
| `ready_for_pickup` | Заказ готов к передаче курьеру. | Партнёр | Заказ ожидает курьера. |

## 2. Delivery statuses

Эти статусы описывают отдельный delivery flow после готовности заказа к доставке.

| Status | Назначение | Кто меняет | Комментарий |
| --- | --- | --- | --- |
| `delivery_pending` | Доставка нужна, но ещё не начат поиск курьера. | Система | Стартовый delivery status. |
| `courier_searching` | AI/admin ищет доступного курьера. | AI Delivery Admin / админ | Клиенту можно показывать мягкий статус поиска. |
| `courier_assigned` | Курьер назначен, но ещё не принял доставку. | Админ / AI recommendation + human approval | Нужен контроль 3 минут. |
| `courier_accepted` | Курьер принял доставку. | Курьер | Доставка подтверждена курьером. |
| `courier_to_partner` | Курьер едет к партнёру. | Курьер | Партнёр видит ожидаемое прибытие, если есть данные. |
| `picked_up` | Курьер забрал заказ у партнёра. | Курьер | Клиент видит, что заказ в пути. |
| `courier_to_client` | Курьер едет к клиенту. | Курьер | Активная доставка клиенту. |
| `delivered` | Заказ доставлен клиенту. | Курьер / админ при споре | После этого заказ может перейти в completed. |
| `delivery_failed` | Доставка не выполнена. | Курьер / админ | Требуется причина и support flow. |
| `cancelled` | Доставка отменена. | Админ | Не равна автоматической отмене заказа без правил. |

## 3. Problem statuses

Проблемные статусы используются для инцидентов и эскалаций.

| Status | Когда использовать | Кто видит |
| --- | --- | --- |
| `partner_delay` | Партнёр не принял заказ или готовит дольше ожидаемого. | Админ, партнёр, поддержка |
| `courier_delay` | Курьер не принял доставку, задержался на pickup или delivery. | Админ, курьер, поддержка |
| `client_not_available` | Клиент не отвечает или не может принять заказ. | Админ, курьер, поддержка |
| `wrong_address` | Адрес неполный, неверный или противоречивый. | Админ, клиент, курьер |
| `item_missing` | Позиция отсутствует при выдаче или доставке. | Админ, партнёр, курьер |
| `payment_problem` | Проблема с оплатой при получении или manual payment. | Админ, finance, поддержка |
| `weather_delay` | Погода влияет на доставку. | Админ, курьер, клиент |
| `admin_required` | Нужен ручной разбор. | Админ, поддержка |

## 4. Courier availability statuses

| Status | Значение | Ограничения |
| --- | --- | --- |
| `offline` | Курьер не на линии. | Нельзя назначать новые доставки. |
| `online` | Курьер готов принимать доставки. | Можно рекомендовать назначение. |
| `busy` | Курьер выполняет доставку. | Новые назначения только по правилам мультизаказа в будущем. |
| `paused` | Курьер временно на паузе. | Нельзя назначать новые доставки до resume. |
| `blocked` | Курьер заблокирован админом. | Нельзя назначать доставки, нужна причина блокировки. |

## 5. Status transition summary

Базовая цепочка:

`new` → `partner_accepted` → `preparing` → `ready_for_pickup` → `delivery_pending` → `courier_searching` → `courier_assigned` → `courier_accepted` → `courier_to_partner` → `picked_up` → `courier_to_client` → `delivered` → `completed`

Отклонение партнёром:

`new` → `partner_rejected`

Проблемная доставка:

`courier_to_partner` / `picked_up` / `courier_to_client` → problem status → `admin_required` → human resolution.

## 6. Notes

- Stop-кнопка не отменяет уже принятые заказы и доставки.
- Для отмены заказа или доставки нужен отдельный cancel flow с причиной.
- Online payments later; в MVP delivery может работать с manual/cash/COD логикой.
- Alcohol delivery не включается. Алкогольные доставки запрещены до юридической проверки и включения отдельного compliance module.
