## Следующий порядок действий и критерий готовности
1. Один (не параллельный) запуск `npm run check:release-source` на итоговой ветке. Записать EXIT и конкретный SHA.
2. Сохранить протокол, создать отдельный Git-коммит, опубликовать интеграционную ветку и, при возможности, Draft PR без объединения с `main`.
3. Проверить совместимость RPC/schema и Auth/REST/Storage только на изолированном staging. Миграции — только после защиты данных, сверки и испытанного отката.
4. Провести роль-ориентированные E2E: клиент → бронь/заказ → оператор → партнёр → курьер; RLS/изоляция, отмены, повторы, аудит.
5. Только после подтверждённых PASS на одном SHA отдельно решать вопрос production/HTTPS/мониторинга.

**Правило продолжения:** открыть эту запись, выполнить `git status -sb && git log -1 --oneline`, прочитать текущие логи тестов, продолжить с первого незакрытого пункта; не повторять завершённые работы и не выдавать mock-проверки за live E2E.
